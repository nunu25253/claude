# 02. 機能一覧

本ドキュメントは本システムの機能を機能カテゴリごとに一覧化したものです。優先度は以下の3段階で表記します。

- **高**：初期リリース（MVP）に必須の機能
- **中**：初期リリース後、早期に追加する機能
- **低**：将来拡張として設計上のみ考慮する機能

機能IDは `F-<カテゴリ番号>-<連番>` の形式とします。用語・エンティティ名は `01_requirements.md` の用語定義に準拠します。

## 1. 認証・アカウント管理（F-01）

| 機能ID | 機能名 | 概要 | 優先度 |
|--------|--------|------|--------|
| F-01-01 | 新規会員登録 | メールアドレス・パスワードでユーザーアカウントを作成する。 | 高 |
| F-01-02 | ログイン | メールアドレス・パスワードでログインし、JWTアクセストークン/リフレッシュトークンを発行する。 | 高 |
| F-01-03 | ログアウト | リフレッシュトークンを失効させる。 | 高 |
| F-01-04 | トークンリフレッシュ | リフレッシュトークンを用いてアクセストークンを再発行する。 | 高 |
| F-01-05 | パスワードリセット | メール認証によるパスワード再設定。 | 中 |
| F-01-06 | プロフィール編集 | ユーザー名・メールアドレス等の変更。 | 中 |
| F-01-07 | ロール・プラン管理 | USER/ADMINロール、FREE/PRO/ENTERPRISEプランの管理（管理者機能）。 | 低 |

| F-03-04 | BuzzScore算出 | 複数の採点戦略を合成し、0〜100点のBuzzScoreを算出する（詳細はF-05参照）。 | 高 |

| F-03-06 | 類似投稿提案 | BuzzScoreやジャンル・投稿種別が近い過去投稿を類似投稿として提示する。 | 中 |

| F-05-02 | 再生数スコア | 再生数（公開されている場合）を採点する（`ViewCountStrategy`）。 | 高 |
| F-05-03 | コメント率スコア | コメント数を投稿規模に対して正規化して採点する（`CommentRateStrategy`）。 | 高 |
| F-05-04 | 投稿形式スコア | 投稿種別（リール/画像/動画/カルーセル/テキスト）ごとの傾向を採点する（`FormatStrategy`）。 | 中 |
| F-05-05 | ハッシュタグスコア | ハッシュタグの数・種類・人気度を採点する（`HashtagStrategy`）。 | 中 |
| F-05-06 | 投稿時間スコア | 投稿時間帯の妥当性を採点する（`PostingTimeStrategy`）。 | 中 |
| F-05-07 | 文章構成スコア | キャプションの構成・読みやすさを採点する（`TextStructureStrategy`）。 | 中 |
| F-05-08 | AI分析結果スコア | AI分析結果の定性評価をスコアに反映する（`AiInsightStrategy`）。 | 高 |
| F-05-09 | BuzzScore合成 | 各戦略のスコアを重み付け合成し、総合BuzzScore（0〜100）を算出する（`BuzzScoreCalculator`）。 | 高 |
| F-05-10 | 採点基準のバージョン管理 | アルゴリズム改善時に旧バージョンとの整合性を保つため、`strategy_version` を付与し再計算できるようにする。 | 低 |

## 14. 定期データ取得バッチ（自動化）（F-14）

| 機能ID | 機能名 | 概要 | 優先度 |
|--------|--------|------|--------|
| F-14-01 | 追跡対象アカウント管理 | `social_accounts.tracking_enabled` により、定期同期の対象アカウントを管理する。投稿URL分析・競合分析で登録されたアカウントはデフォルトで追跡対象になる。 | 中 |
| F-14-02 | 投稿の定期自動取得 | 各SNS公式API（未設定時はスタブ）から追跡対象アカウントの最新公開投稿を定期的に再取得し、`posts` テーブルを新規作成/更新する。非公開データは取得しない。 | 中 |
| F-14-03 | BuzzScore自動再計算 | 定期取得した投稿についてStrategyパターンでBuzzScoreを再計算する（コスト抑制のためAI再分析は行わない）。 | 中 |
| F-14-04 | ランキング自動再構築 | 急上昇(48時間)/週間(7日)/月間(30日)の各ランキングを、全体版・SNS別版で再計算し `rankings` テーブルを更新する。 | 中 |
| F-14-05 | キャッシュ自動無効化 | バッチ完了時に競合分析・ランキングのRedisキャッシュを無効化し、最新集計が反映されるようにする。 | 中 |
| F-14-06 | バッチのスケジュール実行/手動実行 | `batch.sync.enabled=true` かつ `batch.sync.cron` に従ったcron実行、または `POST /api/v1/sync/run` による即時手動実行の両方に対応する。デフォルトはOFF。 | 中 |
