# 00. SNS別 データ取得可否・API権限・規約制約 一覧（全フェーズ共通の前提）

「SNS AIマーケティングOS」の設計・実装にあたり、各SNSで**取得できるデータ／できないデータ**、**必要なAPI権限**、**利用規約上の制約**を先に一覧化する。以降の全フェーズ（Phase1〜17）はこの一覧の範囲内でのみ設計・実装する。

> **注記**: 各社の公式API仕様・利用規約は改定される可能性があるため、本番導入前に必ず最新の公式ドキュメントで再確認すること。本書は設計時点（既存実装 `backend/src/main/java/com/buzzanalysis/infrastructure/external/platform/`）でのコード内コメントと公開情報に基づく設計上の前提であり、法的助言ではない。

## 2. 設計への反映方針

1. **`viewCount` / `shareCount` は「値がnull＝未計測」として扱い、0と混同しない。** 特にXの第三者投稿viewCountのように「そもそも公開APIで取得不可」な指標は、常にnullを返す（Phase1の `NormalizedPost` でこの方針を踏襲する）。
2. **AIによる推定値と実測値を混同しない**という最重要ルールに従い、後続フェーズ（Phase5以降の分析AI等）が「未計測」フィールドから何らかの推定値を生成した場合は、実測値と明確に区別できるフィールド（例: `estimated: true` フラグや別カラム）を必ず設ける。Phase1では推定は一切行わない。
3. YouTube / Threads は現時点で `SocialPlatform` 実装（データ収集）が未着手。**Phase1の正規化レイヤーはこれらのプラットフォームも受け付けられるよう拡張可能に設計するが、実際のデータ収集アダプタ追加は別途「SNS追加フェーズ」として本ロードマップの外側で扱う**（代替案：Phase1〜17の各AI機能はInstagram/TikTok/Xの既存データで先行検証し、YouTube/Threadsのデータ収集アダプタが揃い次第、同じ正規化パイプラインにそのまま接続する）。
4. 商用利用を前提とする場合、X・TikTokは有償/審査制のAPIティアが必要になる可能性が高い。**Phase0（この一覧）の内容は事業判断（どのAPIティアを契約するか）にも影響するため、契約前に必ず各社の最新料金・利用規約を再確認すること。**

## 3. 実現不可・要代替案の項目（現時点）

| 要求（Phase横断） | 課題 | 代替案 |
|---|---|---|
| インプレッション・リーチ・保存数の分析 | 非公開データのため取得不可（最重要ルールで対象外と明記済み） | 公開指標（いいね・コメント・再生数）から算出する「公開エンゲージメント指標」に置き換える。保存数はInstagramでは非公開だが、Pinterestの「Pin保存数」のみ例外的に公開情報として扱える |
| X上の第三者投稿の再生数分析 | 公開APIでは取得不可 | `viewCount = null（未計測）`として扱い、BuzzScore等の算出ロジックは「いいね数+コメント数」ベースの代替指標（既存 `EngagementRateStrategy` の代替計算と同様の方式）にフォールバックする |
| YouTube/Threadsの投稿分析 | データ収集アダプタ未実装 | 正規化レイヤー・AI分析レイヤーはプラットフォーム非依存に設計し、収集アダプタが追加され次第すぐ利用可能にする（Strategy/Factoryパターンによる拡張性を活用） |
